## Module 41 – Data Manipulation: Role of Controller

### 41.1 Controller

**Definition:**
A controller is an intermediary apparatus that handles communication between a computer and other devices.

Roman Urdu: Controller computer aur external devices ke darmiyan communication handle karta hai.

**Important Points:**
- Controller may be mounted on the computer's **motherboard**.
- It may also be a circuit board plugged into a slot on the motherboard.
- Controller connects to peripheral devices through cables.
- External devices connect through a **port**.
- Controllers may have their own memory and simple CPU.
- Controller translates messages and data between computer and peripheral devices.

### 41.2 USB and FireWire

**Universal Serial Bus (USB)** and **FireWire** are standards that allow a single controller to handle different devices.

Examples of USB-compatible devices:
1. Mouse
2. Printer
3. Scanner
4. Mass storage devices
5. Digital cameras
6. Smartphones

### 41.3 Bus

**Bus:** A communication path connecting the CPU, main memory and controllers.

Important:
- Controllers communicate with the computer through the same bus.
- Controllers can monitor signals between CPU and main memory.
- CPU uses STORE-like instructions to send data to a controller.
- CPU uses LOAD-like instructions to receive data from a controller.

**Important Keywords:** Controller, Motherboard, Port, Peripheral Devices, USB, FireWire, Bus, CPU, Main Memory.

## Module 42 – Data Manipulation: Direct Memory Access and Handshaking

### 42.1 Direct Memory Access (DMA)

**Definition:**
The ability of a controller to access main memory directly is known as Direct Memory Access (DMA).

Roman Urdu: Jab controller CPU ke baghair directly main memory access karta hai to isay DMA kehte hain.

**Important Points:**
1. Controller is attached to the computer's bus.
2. Controller can communicate with main memory when CPU is not using the bus.
3. CPU sends a request to the controller.
4. Controller transfers data between disk and main memory.
5. CPU can continue executing other tasks during this transfer.
6. Two activities can happen at the same time.

**Example:**
- CPU requests data from a disk.
- Controller reads the required data.
- Controller transfers data to main memory using DMA.
- CPU continues executing another program.

### 42.2 Advantage of DMA

- Improves computer performance.
- CPU does not remain idle during slow data transfer.
- CPU and controller can perform different activities simultaneously.

### 42.3 Von Neumann Bottleneck

**Definition:**
The central bus becoming an impediment when CPU and controllers compete for bus access is known as the von Neumann bottleneck.

Roman Urdu: Jab CPU aur controllers aik hi bus use karne ke liye compete karte hain aur communication slow hoti hai to is problem ko Von Neumann Bottleneck kehte hain.

**Important:** DMA improves performance, but it also increases bus communication complexity.

### 42.4 Handshaking

**Handshaking:** A coordination process in which communicating devices exchange signals to coordinate data transfer.

Roman Urdu: Devices data transfer se pehle ya uske dauran signals exchange karke aik doosre ko coordinate karte hain.

**Important Keywords:** DMA, Controller, Main Memory, Bus, Von Neumann Bottleneck, Handshaking.

## Module 43 – Data Manipulation: Communication Media and Communication Rates

### 43.1 Types of Communication

Communication between computing devices uses two types of paths:

1. **Parallel Communication**
2. **Serial Communication**

### 43.2 Parallel Communication

**Definition:**
Several signals are transferred at the same time, each on a separate line.

Roman Urdu: Multiple signals aik hi waqt mein different lines par transfer hotay hain.

**Important Points:**
- Several signals transfer simultaneously.
- Data transfer is good.
- Requires complex architecture.

### 43.3 Serial Communication

**Definition:**
Data is transferred one after another.

Roman Urdu: Data aik aik karke transfer hota hai.

**Important Points:**
- Requires a simple data path.
- Data transfer rate is relatively slower than parallel communication.
- USB and FireWire provide high-speed data transfer over short distances.
- Ethernet connections are used for slightly longer distances.

### 43.4 Communication Technologies

**Modem (Modulator-Demodulator)**
- Converts bit patterns into audible tones.
- Used with traditional voice lines.

**DSL (Digital Subscriber Line)**
- Used for faster long-distance communication.

**Cable Modems**
- Used for communication through cable networks.

**Fiber Optics and Coaxial Cables**
- Used for high-definition TV and computer networks.

### 43.5 Communication Rates

**Definition:**
The rate at which bits are transferred from one computing component to another is measured in bits per second (bps).

Important Units:

- **Kbps:** Kilobits per second.
- **Mbps:** Megabits per second.
- **Gbps:** Gigabits per second.

**Important Handout Fact:**

8 Kbps = 1 KB per second.

- USB and FireWire provide several hundred Mbps.

### Difference: Parallel vs Serial Communication

| Parallel Communication | Serial Communication |
|---|---|
| Several signals at the same time | One after another |
| Separate lines | Simple data path |
| Complex architecture | Simple architecture |
| Faster data transfer | Relatively slower |
| Multiple signals simultaneously | Sequential transfer |

**Important Keywords:** Parallel, Serial, Modem, DSL, Fiber Optics, Coaxial Cable, Ethernet, bps, Kbps, Mbps, Gbps.

## Module 44 – Data Manipulation: Pipelining

### 44.1 Nanosecond

**Definition:**
A nanosecond is one-billionth of a second.

1 nanosecond = 1/1,000,000,000 second.

**Important Handout Fact:**
- Light travels approximately 1 foot in a nanosecond.
- CPU requires at least 2 nanoseconds to fetch an instruction from a memory cell 1 foot away.
- 1 nanosecond for sending the read request.
- 1 nanosecond for receiving the instruction.

### 44.2 Throughput

**Definition:**
Throughput refers to the total amount of work a machine can accomplish in a given amount of time.

Roman Urdu: Aik specific time mein computer jitna total kaam complete karta hai usay throughput kehte hain.

### 44.3 Pipelining

**Definition:**
Pipelining is the technique of allowing the steps in the machine cycle to overlap.

Roman Urdu: Jab aik instruction execute ho rahi hoti hai aur next instruction fetch ki ja rahi hoti hai to is technique ko pipelining kehte hain.

**Important Points:**
1. While one instruction is being executed, the next instruction can be fetched.
2. More than one instruction can be in the pipeline at different processing stages.
3. It increases the total throughput of the machine.
4. Individual instruction execution time remains the same.
5. When a JUMP instruction is reached, the benefit of prefetching may not be achieved.
6. Modern machines can fetch several instructions simultaneously.

**Important Difference:**

- Execution Speed: Time required to execute an individual instruction.
- Throughput: Total work completed in a given time.

**Important Keywords:** Nanosecond, Throughput, Pipelining, Machine Cycle, Fetch, Execute, JUMP Instruction.

## Module 45 – Operating Systems: History

### 45.1 Early Computers (1940s and 1950s)

**Important Points:**
- Computers were not very flexible or efficient.
- Machines occupied entire rooms.
- Magnetic tapes had to be mounted.
- Punched cards were placed in card readers.
- Switches had to be set manually.
- Every program was handled as an isolated activity.

### 45.2 Job

**Definition:**
The execution of each program was called a job.

Roman Urdu: Computer par execute hone wale har program ko job kaha jata tha.

### 45.3 Operating Systems Beginning

- Operating systems began as systems for simplifying program setup.
- They helped streamline the transition between jobs.
- A computer operator was hired to operate the machine.
- Users submitted programs, data and instructions to the operator.

### 45.4 Batch Processing

**Definition:**
Batch processing is the execution of jobs by collecting them in a single batch and then executing them without further interaction with the user.

Roman Urdu: Multiple jobs ko aik batch mein collect karke user interaction ke baghair execute karna batch processing hai.

**Important Points:**
- Jobs are collected in a batch.
- Jobs wait in mass storage.
- Operating system executes jobs.
- Users do not interact with jobs during execution.

### 45.5 Job Queue

**Definition:**
A job queue is a storage organization in which jobs wait for execution.

Roman Urdu: Jobs execute hone ka wait aik queue mein karti hain.

### 45.6 First-In, First-Out (FIFO)

**Definition:**
FIFO means that objects are removed from the queue in the order in which they arrived.

Roman Urdu: Jo job pehle aati hai woh pehle execute hoti hai.

**Important:** FIFO = First-In, First-Out.

Note: Handout states that most job queues do not strictly follow FIFO because operating systems may consider job priorities. A higher-priority job can move ahead.

### 45.7 Job Control Language (JCL)

**Definition:**
Job Control Language is a system used to encode instructions explaining the steps required to prepare the machine for a particular job.

Roman Urdu: JCL machine ko job execute karne ke liye prepare karne wali instructions hoti hain.

### 45.8 Interactive Processing

**Definition:**
Interactive processing allows a program being executed to carry on a dialogue with the user through remote terminals.

Roman Urdu: Jab user program execute hotay waqt computer ke sath interact kar sakta hai to isay interactive processing kehte hain.

**Examples:**
1. Reservation systems.
2. Word processing systems.
3. Computer games.

**Important Points:**
- Users can interact with programs during execution.
- Remote terminals are used.
- Users can enter information and receive responses.

**Important Keywords:** Job, Batch Processing, Job Queue, FIFO, JCL, Computer Operator, Interactive Processing, Remote Terminals.
